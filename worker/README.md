# 집계 서버

**받는 것: 사고 번호와 횟수, 그리고 클라이언트가 만든 난수 설치 ID.**
코드·파일 이름·경로·IP·대화는 받지 않습니다.

**사용자는 이 서버를 읽지 않습니다.** 읽기는 깃허브의 공개 집계 파일에서 합니다.
그래서 이 서버가 죽어도 프로그램은 그대로 돕니다.

## 왜 서버를 두나

혼자 쓰는 순위(내 컴퓨터에서 자주 걸리는 것)는 서버 없이 됩니다.
**전체에서 무엇이 자주 걸리는지**는 모으지 않으면 알 수 없고,
그게 「초록불 보고서」의 표본이 됩니다.

## 돈이 나갈 길을 코드로 막았습니다 — 한 번 틀렸다가 고쳤습니다

처음엔 상한을 **요청 수**(5만)에 걸었습니다. 그런데 무료 등급의 진짜 한도는
**KV 쓰기 하루 1,000회**이고 요청 하나당 두 번 씁니다 — 5만이면 한도의 100배입니다.
**우리 사고 E13 그대로**였습니다: «무료 체험 조건을 안 읽고 우리 설정으로 태웠다».

    무료 KV 쓰기 1,000/일 ÷ 요청당 2회 = 하루 500요청 → 여유 두고 400

넘으면 조용히 버립니다. 그리고 설정이 무료 한도를 넘게 바뀌면 **코드가 스스로**
아무것도 안 받습니다.

**이 숫자는 사람이 2026-08-20 에 확인한 값입니다.** 조건은 바뀝니다(E12).
오래되면 다시 읽고 코드의 날짜를 고치세요.

## 조작 방지

숫자는 **순서에만** 쓰입니다. 무엇이 카탈로그에 들어가고 빠지는지는 영원히
사람이 정합니다. 한 설치가 하루에 올릴 수 있는 양에도 상한이 있습니다.

## 배포

    npx wrangler kv namespace create KV      # id 를 wrangler.toml 에 적는다
    npx wrangler deploy
